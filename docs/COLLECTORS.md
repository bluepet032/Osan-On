# 수집처 및 정책 점검표

수집 방식은 공식 API → 공개 피드 → 공개 HTML → 수동 YAML 순으로 고릅니다. 로그인, CAPTCHA, 접근 제한, 호출 한도를 우회하지 않습니다.

| ID | 출처 | 방식 | 범위 | 비고 |
|---|---|---|---|---|
| `gov24` | 정부24 공공서비스(혜택) | 공공데이터포털 REST API(JSON) | 중앙행정기관·공공기관, 경기도와 산하기관, 오산시와 산하기관 중 개인·가구 대상 | 지원조건 코드로 판정 |
| `bokjiro` | 복지로 지자체복지서비스 | 공공데이터포털 REST API(XML) | 오산시, 경기도(시군구 없음) | 정부24와 같은 혜택은 합침 |
| - | 오산시청 홈페이지 | **수집 안 함** | - | robots.txt가 Yeti 외 모든 봇에 `Disallow: /`(2026-10-16 확인) |

이 표는 법률 자문이 아닙니다. 공개 운영 전후에는 각 API의 이용 조건과 사이트 robots.txt를 사람이 다시 확인해야 합니다.

## 정부24 (`pipeline/collectors/gov24.py`)

- `serviceList`와 `supportConditions`를 1,000건씩 끝까지 읽어 서비스ID로 합칩니다(전체 약 1만 1천 건, 각 약 11회 호출).
- **소관 판별**:
  - 기관명이 "오산"으로 시작하면 `osan`입니다(오산시시설관리공단·오산문화재단 포함, "전남바이오산업진흥원"은 제외).
  - 기관 유형이 중앙행정기관·공공기관이면 `national`입니다.
  - 기관명에 "경기"가 있고 시군구가 아니며 다른 시·군 소속이 아니면 `gyeonggi`입니다.
- 사용자구분에 "개인"이나 "가구"가 없는 법인·단체 전용 서비스는 뺍니다.
- **신청기한**:
  - "YYYY.M.D ~ YYYY.M.D"로 시작하는 범위만 날짜로 씁니다.
  - "상시·수시·연중"은 상시로 봅니다.
  - 그 밖의 문장은 기간 미정으로 둡니다. 문장 속 날짜를 마감일로 잘못 읽으면 받을 수 있는 혜택이 마감으로 숨기 때문입니다.
- 신청방법("기타 온라인신청||방문신청")에서 온라인·방문·신청 불필요를 읽습니다.

## 복지로 (`pipeline/collectors/bokjiro.py`)

- `LcgvWelfarelist`를 500건씩 읽고(전체 약 4,800건), 오산시·경기도(시군구 없음)만 남긴 약 100건만 `LcgvWelfaredetailed`로 상세를 읽습니다.
  - 시군구가 비어 있어도 담당 부서("경기도 구리시 보건소")나 제목("수원형 통합돌봄")에 다른 경기도 시군이 있으면 그 시군의 서비스로 보고 뺍니다.
- **대상자 → 조건 코드**:
  - 장애인 JA0328, 보훈대상자 JA0329, 한부모·조손 JA0403, 다자녀 JA0411, 다문화·탈북민 JA0401·JA0402, 저소득 → 중위소득 100% 이하로 옮깁니다.
  - 대상자가 없거나 모르는 값이 있거나 여러 조건 그룹에 걸치면 조건 없음(`null`)으로 두어 "확인 필요"가 됩니다.
- 대상자가 없을 때만 생애주기를 씁니다.
  - 청년(만 19~39세)·중장년(35~64세)·노년(60세 이상)은 신청자 본인의 나이라서, 이어지는 단계는 하나의 나이 범위로 합칩니다. 임신·출산은 JA0301~JA0303으로 옮깁니다.
  - 영유아·아동·청소년은 부모가 신청하는 경우가 많아 신청자 나이와 다를 수 있으므로 쓰지 않습니다. 이런 단계가 섞이거나 범위가 끊기면 조건 없음으로 둡니다.
  - 생애주기는 대략적인 분류라서 `conditions.life`에 단계를 남기고, 판정에서는 범위 안이어도 "가능성 높음" 대신 "확인 필요"로 둡니다. 범위 밖이면 "해당 없음"입니다.
- 시행 종료일이 9999-12-31이면 상시로 보고, 실제 날짜면 그 날을 마감으로 봅니다.

## 두 포털의 중복 (`pipeline/dedupe.py`)

출처가 다르고 소관이 같은(오산시·경기도) 두 혜택은 같은 혜택으로 보고 합칩니다. 조건은 지역명과 낱말 끝의 "지원"·"사업", 따로 쓴 "등"을 뺀 제목이 0.8 이상 비슷하거나, 짧은 쪽(6글자 이상)이 긴 쪽에 포함되는 것입니다. 이렇게 줄인 제목이 4글자 미만이면 합치지 않습니다. 정부24 우선순위(100)가 복지로(90)보다 높아서, 지원조건 코드가 있는 정부24 항목이 대표가 됩니다.

## 공통 규칙

- `pipeline/http.py`의 HTTP 클라이언트는 인증키로 호출하는 공식 API만 쓰므로 robots.txt를 확인하지 않습니다.
- 같은 호스트에는 최소 1초 간격으로 요청하고, 네트워크·5xx 오류는 최대 3회 재시도합니다.
- 페이지 일부라도 실패하거나, 전체 건수에 못 미쳤는데 빈 페이지가 오면 출처 전체를 실패로 처리해 이전 데이터를 유지합니다. 부분 데이터로 혜택이 사라지지 않게 하기 위해서입니다.
- 오류 문구에서 `serviceKey=` 값은 지웁니다.
- 수집기를 추가할 때는 `pipeline/collectors/base.py`의 계약을 구현하고 `registry.py`에 등록합니다. 실제 응답 형식을 본뜬 최소 픽스처로 정상·누락·오류 응답 테스트를 함께 작성합니다(`tests/python/test_gov24.py`, `test_bokjiro.py` 참고).
