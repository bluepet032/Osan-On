# 오산온 P0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 정부24 혜택 데이터를 수집하고, 성별·나이 등 프로필로 혜택을 3단계 판정해 근거와 함께 보여 주는 첫 화면까지 완성한다.

**Architecture:** 기존 Python 파이프라인에 `gov24` 수집기를 추가하고 공모전 수집기를 지운다. `Opportunity` 모델에 `jurisdiction`·`conditions`를 더하고 `domain`/`primary_type` 값을 혜택용으로 바꾼다. 프런트는 새 순수 모듈 `eligibility.ts`로 판정하고, 기존 `OpportunityPage`에 프로필 카드와 판정 탭을 얹는다.

**Tech Stack:** Python 3.14(pytest), React 19 + TypeScript + Vite(vitest), Firebase(P1)

**Spec:** `docs/superpowers/specs/2026-10-16-osan-on-design.md`

## Global Constraints

- 내부 타입 이름 `Opportunity`는 유지하고, 화면 문구만 "혜택"으로 바꾼다.
- API 키는 환경 변수 `GOV24_API_KEY`에서만 읽고, 오류 메시지·JSON·로그에 남기지 않는다.
- 범위: 소관기관명에 "오산시" 포함 → osan, 소관기관명 == "경기도" → gyeonggi, 소관기관유형 == "중앙행정기관" → national. 사용자구분에 "개인"·"가구"가 모두 없으면 제외한다.
- 판정 결과는 `'eligible' | 'check' | 'ineligible'` 세 가지이고, 조건 정보가 없으면 항상 `check`다.
- 화면에 "최종 자격은 원문에서 확인하세요" 안내를 둔다.
- 프로필은 P0에서 `localStorage` 키 `osanon.profile`에 저장한다.

## Review Focus

- 응답 중간 페이지가 실패하는 경우 → 부분 데이터를 쓰지 말고 출처 전체를 실패로 처리해 이전 데이터를 유지한다 (Task 1 테스트).
- 오류 메시지에 `serviceKey=...`가 남는 경우 → 메시지에서 키를 지운다 (Task 1 테스트).
- 연령 조건이 한쪽만 있는 경우(시작만 / 종료만) → 열린 범위로 판정한다 (Task 2 테스트).
- 조건 레코드가 없는 서비스 → `conditions: null` → `check` (Task 1, Task 2 테스트).
- 저장된 프로필 JSON이 깨진 경우 → 빈 프로필로 시작하고 화면이 죽지 않는다 (Task 3 테스트).
