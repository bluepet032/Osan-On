# 오산온(Osan-On) 설계

작성일: 2026-10-16 · 상태: 승인됨(채팅) · 목적: 공모전·과제 제출용 데모 (마감까지 약 30시간)

## 1. 목표

오산시민이 성별·나이(+선택 항목)를 입력하면 오산시·경기도·중앙정부의 복지·지원금·정부 혜택 중
**자신에게 해당할 가능성이 높은 것**을 판정 근거와 함께 보여 주는 정적 웹사이트.
QuestBoard(공모전 모음 사이트) 복제본에서 UI·파이프라인 구조는 유지하고 데이터와 목적만 바꾼다.

성공 기준(데모): 첫 화면에서 성별·나이 입력 → 즉시 "가능성 높음 N건"이 보이고, 각 혜택을 펼치면
"✓ 만 19~34세 ✓ 여성 ? 소득 미입력" 같은 근거와 원문·신청 링크가 보인다.

## 2. 확정된 결정

| 항목 | 결정 |
|---|---|
| 사용 대상 | 공모전·과제 제출용 데모 |
| 데이터 | 정부24 공공서비스(혜택) API(P0) + 오산시청 공고 크롤링(P2) |
| 범위 | 오산시 + 경기도 + 중앙행정기관 |
| 프로필 | 성별, 나이, 소득(중위소득 구간), 가구 상황, 특수 대상, 직업·학적 상태 |
| 저장 | 기존 Google 로그인(Firebase) 유지. 로그인 전에는 브라우저 저장 |
| 매칭 | 규칙 기반 3단계: 가능성 높음 / 확인 필요 / 해당 없음 + 근거 |
| 첫 화면 | 간단 설문(성별·나이) → 결과, "더 정확하게"로 나머지 입력 |
| 유지 기능 | 검색, 주간 요약, 찜·일정·알림함, 상세 조건 필터, 테마, 모바일 레이아웃, 수집 상태(관리자만 보이게) |
| 이름 | 오산온 (Osan-On) |

채팅 설계와 다른 점: 타입 이름 `Opportunity`는 **바꾸지 않는다**. 파이썬·TS·테스트 전반의 이름 변경은
30시간 안에서 비용만 크고 화면에는 드러나지 않는다. 화면 문구만 "혜택"으로 바꾼다.

## 3. 데이터 출처: 정부24 API (확인 완료)

명세: `https://infuser.odcloud.kr/api/stages/44436/api-docs` (Swagger 2.0, 2026-10-16 확인)

- Base: `https://api.odcloud.kr/api`, 인증: 쿼리 `serviceKey` (공공데이터포털 발급, 자동승인, 개발계정 1만 회/일)
- `GET /gov24/v3/serviceList?page&perPage` → 서비스ID, 지원유형, 서비스명, 서비스목적요약, 지원대상,
  선정기준, 지원내용, 신청방법, 신청기한, 상세조회URL, 소관기관명, 부서명, 소관기관유형, 사용자구분,
  서비스분야, 접수기관, 전화문의, 등록일시, 수정일시
- `GET /gov24/v3/supportConditions?page&perPage` → 서비스ID + 조건 코드
  - JA0101 남성, JA0102 여성, JA0110/JA0111 대상연령 시작/종료
  - JA0201~JA0205 중위소득 0~50 / 51~75 / 76~100 / 101~200 / 200% 초과
  - JA0301 예비부모·난임, JA0302 임산부, JA0303 출산·입양, JA0313~0316 농·어·축산·임업인,
    JA0317~0320 초·중·고·대학(원)생, JA0326 근로자, JA0327 구직자, JA0328 장애인, JA0329 국가보훈대상자,
    JA0330 질병·질환자, JA0322 해당사항없음
  - JA0401 다문화, JA0402 북한이탈주민, JA0403 한부모·조손, JA0404 1인가구, JA0411 다자녀,
    JA0412 무주택, JA0413 신규전입, JA0414 확대가족, JA0410 해당사항없음
  - JA1101 예비창업자, JA1102 영업중, JA1103 생계곤란·폐업예정
  - JA12xx(소상공인 업종), JA21xx·JA22xx(법인) — 개인 프로필과 무관하므로 무시
- `serviceDetail`은 건별 호출이라 쓰지 않는다. 목록 응답에 화면에 필요한 필드가 모두 있다.

수집 방식: 두 목록을 `perPage=1000`으로 끝까지 읽어(각 약 11회) 서비스ID로 합친 뒤 로컬에서 거른다.

- 오산: 기관명이 "오산"으로 시작(경기도 오산시, 오산시시설관리공단, (재)오산문화재단, 재단법인오산교육재단) → `"osan"`
- 중앙: 소관기관유형이 "중앙행정기관" 또는 "공공기관"(국민연금공단·한국장학재단 등) → `"national"`
- 경기도: 기관명에 "경기"가 있고 시군구가 아니며 "경기도 ○○시/군" 소속이 아닌 것(경기도, 경기도교육청, 경기복지재단 등) → `"gyeonggi"`
- 사용자구분("개인||가구" 형식)에 "개인" 또는 "가구"가 없는 것(법인·단체 전용)은 제외
- 2026-10-16 실제 수집: 전체 10,969건 → 1,278건(오산 22, 경기도 136, 중앙 1,105). 오산시 소관이 적어 P2 오산시청 크롤링이 보강한다.

신청기한 해석: "YYYY.M.D ~ YYYY.M.D"로 시작하는 범위만 `exact`로 믿는다("5년 이내(2012.7.1. 이후…)" 같은
문장에서 날짜를 뽑으면 받을 수 있는 혜택이 마감으로 숨는다). "상시·수시·연중"은 `ongoing`, 나머지는 `inquiry`("기간 미정").

## 4. 데이터 모델 변경 (pipeline/models.py, src/types.ts, schemas)

- `domain`: 분야 탭 → 정부24 서비스분야 10종
  `living` 생활안정, `housing` 주거·자립, `childcare` 보육·교육, `jobs` 고용·창업, `health` 보건·의료,
  `admin` 행정·안전, `pregnancy` 임신·출산, `care` 보호·돌봄, `culture` 문화·환경, `agriculture` 농림축산어업
  (매핑 실패 시 `living`)
- `primary_type`: 공모전 유형 → 지원 형태 `cash` 현금, `in_kind` 현물, `service` 서비스, `voucher` 이용권,
  `loan` 융자, `reduction` 감면, `other` 기타 (지원유형 부분 일치, 융자·감면을 먼저 봐서 "현금(융자)"는 융자)
- `apply_methods`: 신청방법("기타 온라인신청||방문신청")에서 `online`·`visit`·`none`(신청 불필요). "직접입력"만 있으면 빈 목록
- 추가: `jurisdiction: "osan" | "gyeonggi" | "national"`
- 추가: `conditions: { codes: string[], age_min: int | null, age_max: int | null } | null`
  (`null` = 조건 정보 없음)
- `eligibility` = 지원대상(+선정기준), `benefits` = 지원내용, `summary` = 서비스목적요약,
  `organizer` = 소관기관명(+부서명), `application_url`/`source_url` = 상세조회URL
- `eligibility`/`benefits`는 240자에서 500자로 늘린다(복지 조건은 길다).
- 공모전 필드(`regions`, `prize_manwon`, `fee`, `mode`, `is_adjacent`)는 P1에서 삭제했다.

정규화: 혜택 출처뿐이므로 `normalize`는 IT 키워드 분류(`classify`/`assign_domain`)를 호출하지 않고,
모든 항목을 `publish`(점수 100)로 낸다.

## 5. 매칭 (src/eligibility.ts)

```ts
interface Profile {
  gender?: 'male' | 'female'
  age?: number                 // 만 나이
  income?: 'JA0201' | 'JA0202' | 'JA0203' | 'JA0204' | 'JA0205'
  traits?: string[]            // JA03xx·JA11xx 중 해당하는 것. undefined = 아직 답하지 않음, [] = 해당 없음
  household?: string[]         // JA04xx 중 해당하는 것. undefined/[] 의미는 위와 같음
}
type Verdict = 'eligible' | 'check' | 'ineligible'
judge(item, profile) → { verdict, reasons: { label, ok: true | false | null }[] }
```

그룹별 판정(그룹 간 AND, 그룹 안 OR):

| 그룹 | 조건 코드 | 제약 없음 | 충족 | 미입력 |
|---|---|---|---|---|
| 성별 | JA0101/0102 | 둘 다 있거나 둘 다 없음 | 내 성별 코드 있음 | gender 없음 |
| 연령 | age_min/max | 둘 다 null | 범위 안 | age 없음 |
| 소득 | JA0201~0205 | 하나도 없음 | 내 구간 포함 | income 없음 |
| 개인 특성 | JA03xx | 없음 또는 JA0322 포함 | traits와 교집합 | traits 없음 |
| 가구 | JA04xx | 없음 또는 JA0410 포함 | household와 교집합 | household 없음 |
| 창업·영업 | JA1101~1103 | 없음 | traits와 교집합 | traits 없음 |

- 그룹의 선택지가 **전부** 체크되어 있으면 제약 없음(실데이터 1,258건 중 917건이 소득 5구간 전체 체크). 연령 상한 100 이상은 상한 없음(정부24는 120으로 표기).
- 법인·사업자 코드(JA2xxx)가 있으면 "사업자·기관 대상 포함" 미확인 근거를 더해 `check`로 둔다.
- 하나라도 불충족 → `ineligible`, 아니면 미입력이 하나라도 있으면 → `check`, 모두 충족 → `eligible`
- `conditions === null`(오산시 크롤링 공고 등) → `check` + "지원조건 정보 없음, 원문 확인"
- 근거 문구 예: "✓ 만 19~34세", "✗ 여성 대상", "? 소득 구간 미입력"
- 알려진 한계: 정부24 조건 코드가 없는 혜택도 지원대상 원문에 제한이 있을 수 있다. 결과 화면과
  상세에 "최종 자격은 원문 확인" 안내를 둔다.

## 6. 화면

- `/` 혜택 목록(기존 OpportunityPage 재사용): 상단에 **프로필 카드**
  - 미설정: 성별·나이 2문항 + "결과 보기"
  - 설정 후: 요약("여성 · 만 28세") + "더 정확하게"(소득, 가구, 특수 대상, 직업·학적 체크박스) + "수정"
- 판정 탭: 가능성 높음 N / 확인 필요 N / 전체 N. 프로필이 있으면 기본 "가능성 높음", 없으면 "전체".
  "해당 없음"은 "전체"에서만 보인다.
- 목록은 active + undated(상시·미정)를 함께 보여 준다. 혜택은 대부분 날짜가 없기 때문이다.
- 기본 정렬은 "오산 우선": 오산시 → 경기도 → 중앙, 같은 소관 안에서는 마감 임박순.
- 행: 판정 배지 + 소관 배지(오산시/경기도/중앙). 펼치면 판정 근거, 지원대상, 지원내용, 원문·신청 링크.
- 프로필 저장: 항상 `localStorage('osanon.profile')`에 먼저 쓰고, 로그인 중이면 `users/{uid}/profile/main`에도 setDoc한다.
  계정에 프로필이 없으면 브라우저 값을 올리고, 있으면 계정 값을 브라우저로 내려받는다. 계정 삭제 시 함께 지운다.
- 소관 탭(전체 소관/오산시/경기도/중앙정부, URL `place`)과 분야 탭(모든 분야 먼저), 상세 조건은 "신청 방법" 하나.
- 브랜딩: 헤더·푸터·`<title>`을 "오산온 · 오산시민 맞춤 혜택"으로 바꾼다.
- 메뉴: 혜택 / 주간 요약 / 마감 혜택 / 수집 상태 / 내 혜택함 ("날짜 미상"은 목록에 합쳐지므로 메뉴에서 뺀다)

## 7. 우선순위

- **P0**: 정부24 수집기, 모델 변경, `eligibility.ts`+테스트, 프로필 카드·판정 탭·근거 표시, 브랜딩,
  기존 공모전 수집기 11종 삭제, collect 워크플로에 `GOV24_API_KEY` 시크릿 연결
- **P1**: 분야 탭 문구·소관 탭, 상세 필터(지원 형태·소관) 개편과 공모전 필드 정리, 로그인 시 프로필 Firestore 동기화
- **P2**: 오산시청 공고 크롤링, 주간 요약·찜·일정·알림함 문구와 "내 조건에 맞는 새 혜택" 알림
- **P3**: 수집 상태 관리자 전용(관리자 이메일 확인 후 메뉴·페이지 표시), 디자인 다듬기, e2e

## 8. 오류 처리

- API 키 없음 → 수집기가 명확한 오류("GOV24_API_KEY가 없습니다")로 실패하고, 러너가 기존처럼 이전 데이터를 유지한다.
- 페이지 일부 실패 → 수집 전체 실패로 처리해(부분 데이터로 혜택이 사라지지 않게) 이전 데이터를 유지한다.
- 키 값은 로그·오류 메시지·생성 JSON에 남기지 않는다(오류 문자열에서 URL 쿼리를 지운다).
